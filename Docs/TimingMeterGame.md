# タイミング型 MeterGame

## 起動

`Assets/MeterGame/Scenes/MeterGameExample.unity` を開き、Playで開始する。Gameビューを選択してSpaceキーで操作する。
既存のゲージ維持型は `Assets/MeterGame/Scenes/TensionManagementMinigame.unity`。
専用のコード・素材・テストはすべて `Assets/MeterGame/` 配下に配置する。

## ルール

- 各セットでゲージが0から自動で増える。既定は毎秒0.4、2.5秒でMAX。
- 成功範囲は既定で90〜100%。この範囲に入ってからSpaceを1回押すと成功。
- MAX到達後も既定で0.35秒の猶予がある。開始90%・速度0.4なら、MAX直前の0.25秒と到達後0.35秒の合計約0.6秒が成功受付時間。
- 早押し・猶予を超えた入力・未入力は、そのセットの失敗。押しっぱなしでは次セットの入力にならず、押し直す必要がある。
- 既定は **5セット中3回以上成功**でゲーム成功。成功数が不足すればゲーム失敗。
- 必要成功数に先に到達しても、途中で達成不能になっても、全nセットを最後まで実行する。
- セット数nは2以上、必要成功数mは1以上かつn未満に自動補正する。

## UIと演出

`TensionManagementMinigame` と同じ描画クラス・フォント・CanvasScaler・UI配置を使う。
バーの上に操作案内、右上に現在セットの残り秒数を表示する。

- バー内の枠：成功タイミングの範囲。既定は90〜100%。
- 白いカーソル：自動で増加する現在のゲージ量。
- 右のハート：必要成功数に対する達成率。必要成功数に達すると100%になるが、残りセットは続く。
- 上部：現在のセット番号、成功回数 / 必要成功数、各セットの「成功！」「失敗…」、最終結果。
- 成功時：金色の輝きと拡大のアニメーション。
- 失敗時：紫・青色への変化と沈むような影・縮小のアニメーション。
- 結果表示 → UIのフェードアウト → 非表示で待機 → 次セットを0で準備 → フェードイン → 操作受付を再開。
- 結果表示中・フェード中はゲージ・タイマーを停止し、Spaceは受け付けない。最後のセットもフェード後に最終結果を表示する。

## Inspector

Hierarchy の **MeterGameCanvas → Timing Meter Controller → 難易度・セット・演出設定** で変更する。
初期設定を反映し直すには、Play中にInspectorの **現在の設定で再スタート** ボタン、またはControllerのコンテキストメニューから同名の項目を実行する。Inspector下部で現在のフェーズ・セット番号・成功回数・ゲージ量を確認できる。

| 項目 | 既定値 | 内容 |
| --- | ---: | --- |
| セット数 n | 5 | 全体の試行回数。変更は再スタートで反映 |
| 必要成功数 m | 3 | 全体成功に必要な回数。変更は再スタートで反映 |
| ゲージ増加量 / 秒 | 0.4 | 大きいほどMAXへの到達が速く、成功範囲にいる時間も短くなる |
| 成功範囲の開始位置 | 0.9 | 小さいほど早めに押しても成功。1ならMAX到達後だけ受付 |
| MAX到達後の猶予秒数 | 0.35 | 押し遅れの許容時間。0にも設定可能 |
| セットごとの速度をランダム化 | 無効 | 有効なら各セット開始時に速度倍率を抽選 |
| ランダム速度の最小 / 最大倍率 | 0.85 / 1.15 | 抽選する速度倍率の区間 |
| セットが進むごとの速度加算倍率 | 0 | 0.1なら1、1.1、1.2…倍に高速化 |
| 乱数シード | 0 | 0は開始ごとにランダム。0以外は同じ順序を再現 |
| 結果を表示する秒数 | 1 | 各セットの結果表示時間。0でも結果は記録する |
| 結果アニメーションを有効化 | 有効 | 無効でも結果の色と文言は表示する |
| 結果アニメーションの拡縮量 | 0.035 | 拡大・縮小の強さ |
| 成功時の輝きの回数 | 3 | 結果表示中の輝きの繰り返し回数 |
| フェードを有効化 | 有効 | 無効なら結果表示後に即座に次セットへ切り替え |
| フェードアウト秒数 | 0.25 | UIを消す時間。0で即時 |
| 非表示で待つ秒数 | 0.1 | 消えたまま待つ時間 |
| フェードイン秒数 | 0.25 | UIを表示する時間。0で即時 |

判定・速度は各セット開始時に確定し、途中で変更しても現在のセットの受付範囲が飛ばない。変更は次セットから反映する。
乱数シードは再スタートで反映。演出の設定は次の演出で使用する。
成功色・失敗色は同じCanvasの **Timing Meter Feedback** で調整できる。

## イベントと再利用

Controllerの **On Set Success / On Set Failure** は各セットにつきどちらか1回、**On Success / On Failure** は全セット終了後のフェードイン完了時にどちらか1回発火する。
`Session.Results` から全セットの結果、`SuccessCount`、`CurrentSetNumber`、`Round.Gauge`、`Round.RemainingSeconds`、`IsFinished`、`IsSuccessful` を参照できる。
`RestartGame()` で演出を中断し、UIの透明度・色・大きさとセットの記録をリセットして再開する。
`SubmitPress()` は1回分の押下を受け付ける入力アダプター用API。UIボタンなどの入力を接続でき、結果表示・フェード中の呼び出しは無視する。

## 検証

Unity Test RunnerのEditModeで `TimingMeterTests` と既存の `MeterGameTests` を実行する。
受付時間の両端・早押し・押し遅れ・未入力、MAX後の猶予、全nセットの実行、必要成功数、重複記録防止、速度抽選とシード、シーンのUI配置・参照、結果の色分け、フェード無効時の表示を確認する。

Unity 6000.3.6f1 の検証用コピーで **52件すべて成功**（既存ゲームの30件、新ゲームの22件）。統合テストではPlay Modeに入り、`SubmitPress()` から入力受付を呼んで結果表示・フェード・全体成否イベント・再スタートを検証する。
1920×1080で開始時・セット成功時・セット失敗時・全体結果の描画も確認済み。
