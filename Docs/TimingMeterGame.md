# タイミング型 MeterGame

## 起動

`Assets/MeterGame/Scenes/TimingMeterGame.unity` を開き、Playで開始する。Gameビューを選択してSpaceキーで操作する。
既存のゲージ維持型は `Assets/MeterGame/Scenes/TensionManagementMinigame.unity`。
専用のコード・素材・テストはすべて `Assets/MeterGame/` 配下に配置する。

## ルール

- 各セットでゲージが0から自動で増え、Spaceを押すまでMAX → 0 → MAXと往復し続ける。増加・減少は同じ一定速度で、端では待たずに折り返す。既定は毎秒0.4、片道2.5秒・往復5秒。
- 成功範囲は幅だけを指定する（既定はバー全体の10%）。実際の位置は各セット開始時にバー内へランダム配置され、セット中は固定する。開始・終了位置を指定する設定はない。
- 増加中も減少中も範囲内でSpaceを1回押すと成功。範囲の両端ちょうどの入力も成功になる。幅20%・速度0.4なら片道につき約0.5秒の受付時間がある。
- 前セットからの最小移動割合を指定できる。既定10%は「配置可能な移動幅」の10%で、成功範囲の幅10%なら前セットからバー全体の9%以上離して抽選する。0%なら制約なし。幅100%は全体が成功範囲となるため位置は変わらない。
- 範囲外でSpaceを押すとそのセットは失敗して終了する。未入力・成功範囲の通過・MAXや0への到達では終了せず、往復を続ける。押しっぱなしでは次セットの入力にならず、押し直す必要がある。
- MAX後の待機猶予・制限時間は設けない。成功範囲を調整して難易度を変える。
- 必要成功数に先に到達しても、達成不能になっても全nセットを最後まで実行する。既定は5セット中3回以上成功でゲーム全体の成功。成功数が必要成功数m未満ならゲーム全体の失敗。
- セット数nは2以上、必要成功数mは1以上かつn未満に自動補正する。

## UIと演出

`TensionManagementMinigame` と同じ描画クラス・フォント・CanvasScaler・UI配置を使う。
バーの上に操作案内、右上に現在セットの経過秒数を表示する。

- バー内の枠：成功タイミングの範囲。既定の幅は10%、位置はセットごとに抽選。
- 白いカーソル：自動で増減する現在のゲージ量。
- 右のハート：必要成功数に対する達成率。必要成功数に達すると100%になるが、残りセットは続く。
- 上部：現在のセット番号、成功回数 / 必要成功数、各セットの「成功！」「失敗…」。
- 最終結果：全セット終了後のフェード後に、半透明な黒背景（最前面）とともに画面中央へ表示する。
- 画面下部（横軸の1/4・3/4）にはデフォルメキャラクターを常時表示し、背景の前面・結果オーバーレイの後面に配置する。一定時間ごとに左右へ揺らし、結果表示に遷移すると徐々に直立へ収束して停止する。カヨは揺れの向きに合わせて deformed_kayo_1 / deformed_kayo_2 を切り替える。
- 成功時：金色の輝きと拡大のアニメーション。
- 失敗時：紫・青色への変化と沈むような影・縮小のアニメーション。
- 結果表示 → UIのフェードアウト → 非表示で待機 → 次セットを0で準備 → フェードイン → 操作受付を再開。
- 結果表示中・フェード中はゲージ・タイマーを停止し、Spaceは受け付けない。最後のセットもフェード後に最終結果を表示する。

## Inspector

Hierarchy の **MeterGameCanvas → Timing Meter Controller** で変更する。成功範囲・速度はInspector上部に常時表示する。
「往復速度（% / 秒）」は40なら毎秒40%増減し、片道2.5秒・往復5秒になる。「成功範囲の幅（%）」は1〜100%を指定するスライダーで、位置は指定できない。「位置の最小移動割合（%）」は0〜50%の範囲で、前セットに近すぎる位置を抽選対象から外す。最小移動割合は位置そのものや配置領域を指定する値ではない。片道・往復の時間、片道の範囲内通過時間の目安も表示する。
「乱数シード」は0なら開始・再スタートごとにランダム、0以外なら同じ設定で同じ配置・速度の順序を再現する。位置と速度は独立した乱数列を使うので、速度のランダム化を切り替えても位置の順序は変わらない。Play中の状態欄には今回の成功範囲と使用中のシードを表示する（編集不可）。0で開始した場合も、表示されたシードを入力して再スタートすると再現できる。
ランダム速度・結果演出・フェード・結果イベント・コンポーネント参照は、それぞれの折りたたみ欄で調整する。
初期設定を反映し直すには、Play中にInspectorの **現在の設定で再スタート** ボタン、またはControllerのコンテキストメニューから同名の項目を実行する。Inspector下部で現在のフェーズ・セット番号・成功回数・ゲージ量を確認できる。

| 項目 | 既定値 | 内容 |
| --- | ---: | --- |
| セット数 n | 5 | 全体の試行回数。変更は再スタートで反映 |
| 必要成功数 m | 3 | 全体成功に必要な成功セット数。変更は再スタートで反映 |
| 往復速度（% / 秒） | 40 | 増加・減少に共通の速度。大きいほど成功範囲にいる時間も短くなる。内部値は0.4 |
| 成功範囲の幅（%） | 10 | バー全体に対する幅。1〜100%。内部値は0.1 |
| 位置の最小移動割合（%） | 10 | 配置可能な移動幅に対する前セットからの最小距離。0〜50%。内部値は0.1 |
| セットごとの速度をランダム化 | 無効 | 有効なら各セット開始時に速度倍率を抽選 |
| ランダム速度の最小 / 最大倍率 | 0.85 / 1.15 | 抽選する速度倍率の区間 |
| セットが進むごとの速度加算倍率 | 0 | 0.1なら1、1.1、1.2…倍に高速化 |
| 乱数シード | 0 | 位置・速度の抽選に使用。0は開始ごとにランダム。0以外は同じ順序を再現 |
| 結果を表示する秒数 | 1 | 各セットの結果表示時間。0でも結果は記録する |
| 結果アニメーションを有効化 | 有効 | 無効でも結果の色と文言は表示する |
| 結果アニメーションの拡縮量 | 0.035 | 拡大・縮小の強さ |
| 成功時の輝きの回数 | 1 | 結果表示中の輝きの繰り返し回数 |
| フェードを有効化 | 有効 | 無効なら結果表示後に即座に次セットへ切り替え |
| フェードアウト秒数 | 0.25 | UIを消す時間。0で即時 |
| 非表示で待つ秒数 | 0.1 | 消えたまま待つ時間 |
| フェードイン秒数 | 0.25 | UIを表示する時間。0で即時 |

表はスクリプトの既定値。保存済みの `TimingMeterGame.unity` では成功範囲の幅を3.5%に設定している。

幅・最小移動割合・速度は各セット開始時に確定し、途中で変更しても現在のセットの受付範囲が飛ばない。変更は次セットから反映する。
乱数シードは再スタートで反映。演出の設定は次の演出で使用する。
成功色・失敗色は同じCanvasの **Timing Meter Feedback** で調整できる。

## イベントと再利用

Controllerの **On Set Success / On Set Failure** は各セットの判定時に成否に応じてどちらか1回発火する。範囲外でSpaceを押した場合は **On Set Failure**。全セット終了後のフェードイン完了時に、成功数が必要数以上なら **On Success**、未満なら **On Failure** が1回発火する。
`Session.Results` から全セットの結果、`SuccessCount`、`CurrentSetNumber`、`Round.Gauge`、`Round.ElapsedSeconds`、`IsFinished`、`IsSuccessful` を参照できる。
`RestartGame()` で演出を中断し、UIの透明度・色・大きさとセットの記録をリセットして再開する。
`SubmitPress()` は1回分の押下を受け付ける入力アダプター用API。UIボタンなどの入力を接続でき、結果表示・フェード中の呼び出しは無視する。

## 検証

Unity Test RunnerのEditModeで `TimingMeterTests` と既存の `MeterGameTests` を実行する。
往復の両端・同速度・長いフレームで複数回折り返す動作、往路・復路それぞれでの成功と範囲外入力による失敗、範囲の両端、未入力での継続、幅の補正と100%幅、セットごとの位置抽選・最小移動量・幅の保持、シードでの再現と速度抽選との独立性、次セットへの反映、表示範囲との一致、全nセットの実行と全体成否、重複記録防止、速度抽選、シーンのUI配置・参照、結果の色分け、フェード無効時の表示を確認する。

統合テストではPlay Modeに入り、範囲外入力による失敗・折り返し後の成功・結果表示・フェード・各セットと全体の成否イベント・演出中の重複入力の無視・再スタートを検証する。

Unity 6000.3.6f1 の検証用コピーで81件すべて成功（既存ゲーム30件、タイミング型51件）。
